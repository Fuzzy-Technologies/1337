# Internal original-response command boundary

The `response capture` command exposes explicit planning or approved acquisition
through the same SDK owners. `response replay` verifies an existing original
receipt offline. Separate `response check-headers` supplies explicit original
receipt/Target/scope/owner, current typed policy, analysis reference and PASSIVE
opt-in to the existing offline SDK once with fresh original revision bases.
`response replay-headers` verifies a retained assessment with workspace and actual
Observation reference only. Header actions supply no plan/events/capture/job or
execution grant and cannot turn crawl digests into original header custody.

`CheckOriginalHeaders` is an internal command handoff, not a new authority owner.
Policy and selected actor references remain explicit; default owner selection is
attribution only. JSON preserves SDK commit/reference outcomes; completed or
already-applied checks return 0, denial 3, failed/partial state 4 and invalid input 2.
Original source acquisition itself remains unassessed, and no action manufactures
permission or accepts caller headers. Historical integrity refusal returns 4.

See `docs/OWNED_RESPONSE_CAPTURE_CONTRACT.md`.
The [header operator guide](https://github.com/Fuzzy-Technologies/1337/blob/develop/docs/NATIVE_RESPONSE_HEADER_CHECK.md)
documents actual commands, original source prerequisites and historical replay limits.
