# fuzzy1337.shell

Foreground `trace ioc import|inspect` forwards explicit quoted arguments to the
Internal IOC handler and preserves its actual terminal status. Shell context
supplies no missing file, source, scope, read consent, snapshot or original receipt
anchor. The complete `trace` namespace, including malformed input, is protected
from local/native argument history and empty-line replay before dispatch. Import
retains original evidence with honest acknowledgement; inspection does not acquire
or save evidence/Core/workspace state and performs no external source discovery.

Foreground `runtime import <docker-inspect|kubernetes-list>` forwards explicit quoted CLI
arguments to the Internal runtime handler and preserves its actual exit status.
The Experimental version-one command requires source selection, existing
HOST (`--host`) or declared cluster ASSET (`--cluster`), scope and exact revision
bases; shell context supplies none of them. Cross-profile anchor flags fail before
acquisition. Both profiles retain original manifest context and three independent
save acknowledgements; nominal Kubernetes associations remain UNKNOWN access.
Runtime arguments are excluded from local/native input history before dispatch,
and empty-line replay retains only the canonical namespace. Quoted Windows
paths preserve spaces and backslashes through the shared argument parser.

Foreground `ci scan` preserves explicit CLI arguments and predicate/failure exit
statuses. CI input paths and criteria are excluded from persisted/replayed
argument history before the owning consumer executes.

The interactive shell shares the explicit local intelligence commands with the
product CLI. Intelligence command arguments are excluded from persisted history;
the same receipt, scope and model-save boundaries apply in both interfaces.

Foreground `scan config` uses the same explicit five-case configuration adapter
as the CLI. Product command arguments remain excluded from persisted history;
shell selection never supplies source paths, scope or SAFE approval.

Foreground `report export` also admits explicit HTML and JUnit formats through
the same owner-verified snapshot and publication consumer as JSON and SARIF.
Shell context never supplies missing input or destination selections.
