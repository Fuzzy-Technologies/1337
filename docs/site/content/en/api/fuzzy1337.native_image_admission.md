# Internal original native Trivy admission

This Internal consumer verifies the six immutable original executed VERSION/SCAN
records from `native_image_capture` before proposing canonical image, installed
package and Finding model objects. Original receipt provenance, exact invocations,
event streams, selected material, owner/read consent, scope, policy and full
VERSION prerequisite digest remain bound. Observed VERSION never rewrites its
original unknown-version invocation.

`ApplyVerifiedNativeTrivyImages` requires original typed producer captures and
successful custody. It reuses the existing provider-independent native identities
and verified Finding ingestion, preserving canonical triage and model schema.
It starts no process, issues no execution grant, writes no evidence and performs
no model or workspace save. The caller owns the separate CAS persistence.

`VerifyNativeTrivyImageReplay` verifies retained original manifests and receipts
from an existing or relocated owning workspace without opening old selected
binary/archive/database files. Failed or refused SCAN facts remain descriptive;
partial stdout is never interpreted as successful empty inventory. Recorded
authorization values grant no current permission, and content addresses establish
retained consistency rather than publisher authenticity.

Legacy three-role health-based native ingestion and the isolated synthetic image
family remain compatible. Native SDK execution grants and the native CLI/job
workflow remain separate work. ADR 0067 and `docs/NATIVE_IMAGE_ADMISSION.md` define
this consumer and its owned/genuine functional evidence boundaries.
