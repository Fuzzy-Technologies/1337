# Documentation validation and publication

The [source contract](SOURCE_DOCUMENTATION.md),
[audit](SOURCE_DOCUMENTATION_AUDIT.md), and
[blueprint tooling](site/README.md) define the authored inputs. The
[composer](PAGES_COMPOSITION.md) joins the retained Jekyll product site and static
API reference. Publication is a separate protected-branch operation.

## Reproduce the gate

The `Documentation` workflow uses Python 3.11 and the repository's pinned uv.
Documentation dependencies have their own fully hashed transitive lock; none are
added to the product wheel's runtime requirements.

```bash
uv sync --locked --extra dev
uv pip install --python .venv/bin/python --require-hashes -r docs/requirements-api.lock
.venv/bin/python tools/documentation_publication_policy.py .github/workflows/documentation.yml
.venv/bin/python tools/source_documentation_audit.py --check
.venv/bin/python tools/locale_documentation.py validate --output _build/docs/locales.json
.venv/bin/python tools/build_api_reference.py
.venv/bin/python tools/verify_documentation_render.py
.venv/bin/python tools/prepare_product_site.py --output _build/product-source
```

The strict builder provisions a fresh environment outside the checkout, installs
the new wheel without runtime dependencies, rejects runtime imports and dynamic
inspection, compares every packaged Python source byte with the checkout, and
renders twice into fresh temporary output outside the checkout before copying
validated public files to the artifact staging area. `SOURCE_DATE_EPOCH` fixes generated dates to the
input commit timestamp. Both render inventories are retained for failure diagnosis. Different generated bytes or modified tracked
inputs fail. Bounded subprocess deadlines make hung tools observable failures.

The browser proof needs real Chrome/Chromium. It loads local formula resources
offline, checks actual SVG glyph output for representative inline/block formulas,
and fails when no browser is available. The fixed first-party renderer uses
`--no-sandbox` inside the disposable CI runner; it receives only reviewed local
documentation output, has no deployment authority, and denies remote DNS.
Markup or JavaScript-resource presence alone does not prove formula rendering.

Build staged product sources with the official pinned `actions/jekyll-build-pages`
action as the workflow does, or an equivalent installed GitHub Pages Jekyll stack:

```bash
jekyll build --source _build/product-source --destination _build/product-site
mkdir -p _build/pages
.venv/bin/python tools/compose_documentation.py \
  --product-site _build/product-site --api-root _build/api-reference \
  --output _build/pages/site --base-path /1337 --revision "$(git rev-parse HEAD)"
```

The API renderer excludes generated source maps, the optional intersphinx binary
inventory and the compressed sitemap; the HTML, XML sitemap, search data and
rendering assets remain byte-preserved.

Staging copies an explicit reviewed allowlist. Source code, wheels, credentials,
and analysis reports cannot enter Jekyll merely because they exist in the
checkout. Composition rejects collisions, private paths, unsupported file types,
symlinks, path escapes, broken HTML links and anchors. CSS/JavaScript-generated
references and remote destinations are outside the offline HTML link gate.

## Evidence and failure behavior

`_build/docs/api-build.json` records installed-wheel identity, import denial,
complete generated file hashes, reproducibility and tracked-source immutability.
`_build/docs/locales.json`, `render.json`, and `tool-coverage.json` retain locale,
real SVG rendering and branch coverage evidence. Every documentation tool must
remain strictly above 80% combined statement/branch coverage; the same existing
per-module coverage checker enforces this independently of product coverage.
The composition manifest binds artifact identity and source inventories to the
full publication commit SHA.

Source manifests are validated before reads: traversal, symlink components and
paths outside the selected project are rejected. Canonical unit hashes, review
accountability and locale states retain the upstream `fuzzy-doc-unit-v1`
semantics. RU/zh-cn content currently uses visible English fallback; no approval
is generated. Non-missing translation states are rejected by the initial renderer
until reviewed translation selection is implemented.

PRs and `develop` build and validate without deployment permissions. Only a push
to protected `master` can enter the `github-pages` deployment job, which depends
on the entire successful gate and uploads one official composed artifact.
Package publication is separate. Deploying also requires repository Pages source
to be GitHub Actions and the normal protected environment/branch configuration;
this implementation does not bypass owner review or publish from a PR.

Failures prevent upload/deployment; an old successful artifact never covers a
failed fresh build. Rollback means rebuilding an accepted prior protected-branch
commit through the same gates. Restore that commit through normal reviewed Git
history rather than editing generated HTML or disabling validation. Retain the
corresponding Actions artifact and manifest for traceability.
