## Digest

1337 Security Workbench v0.3.0 makes bounded security work reproducible: install the
core, find one real issue in an owned local fixture, retain its evidence and inspect
or export the saved result after the target stops. Human, CLI-capable AI agent and
CI operators share explicit scope, approvals and the same durable model. Optional
Nmap, Nuclei and Trivy workflows extend that core. Interfaces remain experimental;
this is an early Community product with explicitly selected capabilities.

## What's Changed

### Added

- A dependency-free installed core with an owned status-only local demo and a
  [complete Git HEAD exposure recipe](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/OWNED_GIT_HEAD_RECIPE.md).
  The latter creates one LOW Finding and checks a separately approved fixed
  control using only CPython and 1337.
- Selected HTTP discovery and first-party web checks; optional governed
  [Nmap port scanning](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/PORT_SCAN.md)
  and [Nuclei checks](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/NUCLEI_WEB_CHECKS.md)
  retain original provider results and attributable canonical facts.
- [Finite raw Nmap profiles](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/RAW_CLI.md)
  preserve native argument order, stdout/stderr and exit status, with exact-plan
  confirmation and read-only receipt replay.
- [Native image scans](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/NATIVE_IMAGE_WORKFLOW.md)
  use selected archives and provisioned offline Trivy data.
  [Local Docker image export](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/LOCAL_IMAGE_REFERENCE.md)
  records an immutable archive and config pin; scanning requires separate scope
  and approval and verifies that same config identity before model application.
- [Native configuration checks](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/NATIVE_CONFIGURATION.md)
  consume selected Dockerfiles or already-rendered Kubernetes manifests, retaining
  original source/rule/location evidence. No configuration renderer is supplied.
- A minimal read-only [saved image SBOM view](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/IMAGE_SBOM_VIEW.md)
  joins nested packages, declared licenses and supplied Docker-use associations
  with verified original evidence. License compliance and runtime reachability
  are not inferred; broader semantics continue in M4.
- Durable workspaces and JSON, SARIF, HTML and JUnit report exports for reviewing
  actual results after execution ends.
- Release delivery checks bind clean-install verification, wheel/sdist hashes and
  the original versioned API archive. Publication results belong to Validation;
  source tests alone do not establish a published package.

## Try useful work

Install the exact release in a clean environment:

```sh
python -m venv .venv
.venv/bin/python -m pip install 1337==0.3.0
.venv/bin/1337 --version
.venv/bin/1337 doctor
```

On Windows use `.venv\Scripts\python.exe` and `.venv\Scripts\1337.exe`.
On POSIX, a short first result is:

```sh
mkdir artifacts
.venv/bin/1337 demo local artifacts/first-run --json
```

Expect exit **3**, `approval_required`, and no demo root. Read its actual finite
loopback-only plan. If you approve exactly that invocation:

```sh
.venv/bin/1337 demo local artifacts/first-run --approve-safe-http --json
.venv/bin/1337 workspace open artifacts/first-run/workspace --json
.venv/bin/1337 report export artifacts/first-run/workspace \
  --format html --output artifacts/first-run.html --json
```

Expect exit **0**, confirmed target teardown, model revision **3**, six objects,
three verified acquisitions and zero Findings. Inspect the HTML after the target
has stopped. For an attributable Finding rather than discovery alone, copy the
[complete owned Git HEAD recipe](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/OWNED_GIT_HEAD_RECIPE.md):
it includes the standalone nonsecret fixture, explicit policy/scope, exact-plan
confirmation, positive/fixed controls and JSON/HTML/SARIF export. Optional tools
are unnecessary for both examples.

For an external AI agent, use the version-pinned
[agent quickstart and prompt](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/AGENT_QUICKSTART.md).
For GitHub Actions or GitLab, use the
[CI quickstart](https://github.com/Fuzzy-Technologies/1337/blob/v0.3.0/docs/CI_QUICKSTART.md)
and predeclare approval only after reviewing its fixed local plan.

## Notes

The package version is a final numeric `0.3.0`; early-product maturity is not a
Python prerelease suffix. Linux ownership-backed runtime paths and optional
provider requirements remain explicit. General authenticated DAST, unrestricted
SPA/API testing and complete application-wide scanner comparisons are not
claimed by these bounded capabilities. Consult the version-pinned documentation
for supported commands and known exclusions.

The finite Juice Shop comparison covers six executions (two tracks across three
owned cases). Its accepted component checkpoint observed two positives and four
unproven results; this is neither an absolute scanner-accuracy measurement nor a
broad ranking. The native configuration component checkpoint executed eleven
installed cases. Earlier local-image checkpoint evidence covers two actual owned
daemon cases at its recorded source revision. Exact integrated test and
installation results belong to Validation above.

Existing output roots and files are refused; retain the complete workspace and
evidence rather than deleting them to rerun a failed operation. Upgrade by
installing the exact version in a clean environment; keep older evidence bundles
and consult Compatibility before depending on an Experimental interface.
